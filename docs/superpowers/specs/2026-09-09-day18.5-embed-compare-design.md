# 2026-09-09 — Day 18.5 Embed-Compare Page design

> **Status**: Implemented (Day 18.5)
> **Date**: 2026-09-09
> **Deciders**: 老大 + Claude

## Context

Day 18 chunk 调优（heading 6/9 → 7/9，paragraph 7/9 → 8/9）刚完成。肥老大要求在页面上实现一个综合 embed 可视化：① 汉字输入 → 模型 embedding 过程 + 结果可视化；② 与 lancedb 库内向量对比过程可视化；③ 通过 env 里的 reranker 模型对结果裁判。

**路线表风险**：3 个核心概念（embed 可视化 + lancedb 对比 + reranker 集成）必须塞一天 —— 违反「每 day ≤1 个核心概念」节奏铁律。**风险预案**：每 commit 独立可验证 + 5 闸必跑 + Chrome MCP 端到端。

**Day 18.5 探针确证 dev 网关 qwen3-reranker-4b 接口**：
- Endpoint: `POST {baseUrl}/rerank`（baseUrl 含 `/v1`）
- Request: `{ model, query, documents: string[], top_n? }`
- Response 200: `{ id, results: [{ index, relevance_score, document: { text } }], meta: {...} }`
- relevance_score 实测范围 [0, 1]（探针返回 0.905 / 0.009 / 0.002）

## Decision

### 1. 新增 `libs/reranker/`（完整 lib 层）

```ts
// libs/reranker/rerank.ts
export interface RerankRequest {
  readonly query: string;
  readonly documents: readonly string[];
  readonly topN?: number;
  readonly model?: string;            // 默认 'qwen3-reranker-4b'
  readonly baseUrl?: string;          // 默认 OPENAI_BASE_URL
}

export interface RerankHit {
  readonly index: number;              // 原 documents 数组下标
  readonly score: number;             // relevance_score ∈ [0, 1]
  readonly text: string;
}

export interface RerankResult {
  readonly id: string;
  readonly hits: readonly RerankHit[]; // 按 score 降序
  readonly meta: { readonly inputTokens: number };
}

export async function rerank(
  req: RerankRequest,
  apiKey: string,
  signal?: AbortSignal,
): Promise<RerankResult | null>  // null = 调用失败（不抛）
```

`POST {baseUrl}/rerank`，body `{ model, query, documents, top_n }`。错误：missing apiKey → `RangeError`；HTTP !2xx / JSON 解析失败 → 返回 `null` + console warn。

### 3. `apps/api/src/rag-rerank.ts` 后端 handler

`POST /rerank` 接受 `{ query, hits: Hit[] }`，调 `libs/reranker.rerank` 重排，合并原 Hit 字段（chunkId / sourceLabel / chunkKind / score / content）→ 返回 `{ reranked: Hit[] (with relevance_score added), phases }`。

### 4. `apps/web/src/views/embed-compare/` 新 view 层

- `EmbedCompare.vue` 容器（输入框 + namespace 单选 + 3 个 panel）
- `PanelEmbed.vue` Panel A：单文本 embed + 2D 散点（输入点 + SAMPLE_CORPUS 库内 9 个）
- `PanelCompare.vue` Panel B：top-K cosine 距离热图（输入 vs 5 个 hit + 5 个 hit 之间）
- `PanelRerank.vue` Panel C：双 score 对比（lance cosine similarity vs reranker relevance_score）
- `api.ts`：`fetch /api/search` + `fetch /api/rerank` + `warnDevKeyOnce`

### 5. 路由：新增 `#/embed-compare`

- App.vue 加 `v-else-if="route === '/embed-compare'"` 分支
- LeftMenu.vue 加 Embed-Compare 入口（仿 Embed 入口）

## Consequences

**正面**：
- 综合可视化页一次性展示 embed / 检索 / reranker 三阶段
- 后端 /api/rerank 可独立被前端调用，未来可扩展到 Agent RAG
- 不动 EmbedDemo 4 panel（day 12 已有独立路由 #/embed-demo）

**负面**：
- 单 day 3 个核心概念 = 节奏铁律违反，回归风险高
- dev 网关 reranker relevance_score 区分度可能低（探针已证 0.009 / 0.002 这种近 0 值）—— 真实裁判能力后续评估
- 库 + 后端 + 前端三层都要改，commit 数 ~12

**反转条件**：
- 如果 5 闸必跑 5/5 不绿 → 立即停，回溯找根因（不绕开）
- 如果 Chrome MCP 实测 7 步手测任一步失败 → 修根因，不加 if 兜

## 反例（5 个必须能处理）

1. ✅ 后端 OPENAI_API_KEY 缺失 → 返回 500 ApiError.env_missing
2. ✅ 后端 reranker 调用失败 → 返回 502 ApiError.upstream_failure
3. ✅ 前端缺 VITE_OPENAI_API_KEY → 红 banner 显示（沿用 EmbedDemo 模式）
4. ✅ PanelRerank reranker 调用失败 → 显示"reranker 调用失败"红字，不阻塞 PanelA/B
5. ✅ top-K 不足 5（如小语料）→ 显示实际数量，不抛错
